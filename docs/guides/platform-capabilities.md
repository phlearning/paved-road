# Platform capabilities

A service turns on platform capabilities in its `values.yaml`. The shared
chart and the platform operators do the rest.

## PostgreSQL database

```yaml
postgres:
  enabled: true
  extensions: [vector]   # optional, for example pgvector
  storage: 1Gi
```

The CloudNativePG operator creates a PostgreSQL 18 cluster named
`SERVICE-db` with a database `app` owned by the role `app`. The connection
string reaches the service and its jobs as the `DATABASE_URL` environment
variable, read from the `SERVICE-db-app` secret generated by the operator. No
password ever appears in Git.

## Jobs after each deployment

```yaml
jobs:
  - name: migrate
    args: ["python", "-m", "app.migrate"]
```

Each job runs the service image with the same environment, after every
successful deployment: Helm post-install and post-upgrade hooks, which Argo
CD runs as PostSync hooks. Use it for database migrations or indexing. The
previous run is kept until the next deployment so its logs stay readable:

```bash
kubectl -n SERVICE logs job/SERVICE-migrate
```

## Secrets

```yaml
secrets:
  API_KEY: AgB3...   # written by platformctl seal
```

Values are encrypted with Sealed Secrets and reach the service as environment
variables. See the secrets guide for how to add one.

## Shared language model

On the full profile the platform runs an Ollama model server at
`http://ollama.ai.svc:11434` with the `qwen3:1.7b` model. Services call it
instead of shipping their own model runtime. On the lite profile it is not
installed: use a hosted model API with a sealed API key.

## Environment variables and resources

```yaml
env:
  - name: LOG_LEVEL
    value: debug

resources:
  requests:
    cpu: 100m
    memory: 256Mi
  limits:
    memory: 512Mi
```

## Custom hostname

```yaml
ingress:
  host: orders.localhost   # defaults to SERVICE.localhost
```
